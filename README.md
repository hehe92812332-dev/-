# PT 브릿지 (PT Bridge)

물리치료사와 환자를 잇는 임상 지식 플랫폼.

- **환자 Q&A**: 환자·보호자가 원하는 보석 등급의 치료사, 또는 특정 치료사(1:1)에게 질문
- **임상 토론**: 서류 심사를 마친 치료사 전용 케이스 토론
- **등급 라운지**: 같은 보석 등급 치료사끼리의 채팅방 (스터디 공지 고정)
- **보석 등급제 (1~8등급 + 원석)**: 경력 · 물리치료학회 인정 교육 시간 · 석/박사 학위를 **모두** 충족한 가장 높은 등급

  | 등급 | 보석 | 경력 | 학회 인정 교육 | 석·박사 | 질문 비용 |
  | --- | --- | --- | --- | --- | --- |
  | 1 | 다이아몬드 | 15년+ | 500시간+ | 필요 | 50 |
  | 2 | 루비 | 15년+ | 500시간+ | – | 42 |
  | 3 | 사파이어 | 10년+ | 400시간+ | 필요 | 35 |
  | 4 | 에메랄드 | 10년+ | 400시간+ | – | 28 |
  | 5 | 자수정 | 5년+ | 300시간+ | 필요 | 22 |
  | 6 | 토파즈 | 5년+ | 300시간+ | – | 17 |
  | 7 | 오팔 | 3년+ | 200시간+ | 필요 | 13 |
  | 8 | 진주 | 3년+ | 200시간+ | – | 10 |
  | – | 원석 | 8등급 미만 면허 인증 회원 | | | 5 |

  질문 1건은 1:1 지정 할증을 포함해도 **최대 50토큰(5,000원)**. 충전은 **최소 300토큰(30,000원)**부터.
- **토큰 경제**: 충전(카드·카카오페이·네이버페이·토스페이·휴대폰) → 질문 시 에스크로 → 채택 시 답변자에게 지급(수수료 15%) → 3일 정산 대기 → 수익 토큰만 현금 환전(원천징수 3.3%)
- **만족도 온도**: 당근 매너온도 방식, 36.5°C 시작. 질문자↔답변자 양방향 평가, **블라인드 공개**(상대도 평가했거나 7일 경과 시 반영)

정책 값(등급 조건, 비용, 수수료, 환전 기준 등)은 모두 `src/lib/config.ts` 한 곳에 있습니다.

## 두 가지 실행 모드

| | 데모 모드 | 서버 모드 (실서비스) |
| --- | --- | --- |
| 설정 | `NEXT_PUBLIC_APP_MODE` 비움 | `NEXT_PUBLIC_APP_MODE=server` |
| 데이터 | 브라우저 localStorage + 시드 | PostgreSQL |
| 로그인 | 우측 상단에서 데모 계정 전환 | 카카오·네이버 (Auth.js) |
| 결제 | 가상 결제 | 토스페이먼츠 (테스트/라이브 키) |
| 치료사 인증 | 자동 승인 | 서류 업로드 → 관리자 심사 |

두 모드 모두 같은 규칙 엔진(`src/lib/ledger.ts`)을 씁니다. 서버 모드에서는 이 규칙이 DB 트랜잭션(SERIALIZABLE + 지갑 행 잠금) 안에서 실행됩니다.

### 데모 모드로 바로 보기

```bash
npm install
npm run dev        # http://localhost:3000
```

### 서버 모드로 로컬 실행

```bash
docker compose up -d                 # PostgreSQL 16
cp .env.example .env.local           # 아래 값 채우기
#   DATABASE_URL=postgres://ptb:ptb@localhost:5432/ptbridge
#   AUTH_SECRET=<openssl rand -base64 32>  ENCRYPTION_KEY=<openssl rand -base64 32>
#   DEV_LOGIN=true  PAYMENTS_PROVIDER=mock  CRON_SECRET=아무값  ADMIN_EMAILS=admin@ptbridge.dev
npm run db:migrate
npm run db:seed                      # 데모 데이터 (u-patient@demo.ptbridge 등, 관리자 admin@ptbridge.dev)
npm run dev
```

`DEV_LOGIN=true`면 로그인 화면에 이메일만으로 들어가는 개발용 로그인이 생깁니다. production 빌드에서는 항상 꺼집니다.

## 구조

| 경로 | 설명 |
| --- | --- |
| `src/lib/config.ts` | **정책 값**: 보석 등급 조건, 질문 비용, 토큰 상품, 수수료, 환전·환불 조건, 사업자 정보 |
| `src/lib/ledger.ts` | **규칙 엔진**: 충전·결제취소·멤버십·질문·현상금·채택·팁·환전·신고·차단·평가·자동정산 |
| `src/lib/tier.ts`, `manner.ts` | 등급 판정, 만족도 온도(블라인드 공개 포함) |
| `src/lib/store.tsx` | 화면 ↔ 데이터 연결 (데모: localStorage / 서버: `/api` 호출) |
| `src/server/db/schema.ts` | DB 스키마 (Drizzle ORM). 마이그레이션은 `drizzle/` |
| `src/server/runner.ts` | 규칙 엔진을 DB 트랜잭션 안에서 실행하고 바뀐 행만 저장 |
| `src/server/snapshot.ts` | 로그인한 회원이 볼 수 있는 범위로만 데이터 제공 (타인 지갑·평가자·다른 등급 채팅 비공개) |
| `src/server/payments.ts` | 토스페이먼츠 승인·취소·빌링(정기결제), 예약 작업 |
| `src/auth.ts` | 카카오·네이버 로그인, 관리자 지정 |
| `src/app/api/*` | 액션, 결제, 온보딩·서류, 관리자, 크론, 회원 탈퇴 API |
| `src/app/admin` | 관리자 콘솔: 서류 심사, 신고 처리, 환전 이체, 결제 내역, 처리 기록 |

### 보안·개인정보 처리

- 면허번호·환전 계좌·정기결제 빌링키는 AES-256-GCM으로 암호화해 저장 (`ENCRYPTION_KEY`)
- 증빙 서류는 본인과 관리자만 열람, 관리자 조치는 `admin_logs`에 기록
- 결제 금액은 서버의 상품 정보로만 결정하고, 승인 시 금액 대조와 중복 승인 차단. 토큰 지급에 실패하면 결제를 자동 취소
- 잔액 음수는 DB CHECK 제약으로도 차단, 동시 요청은 직렬화 충돌 시 재시도
- 휴대폰·주민등록번호가 포함된 질문·답변·채팅은 등록 단계에서 거부
- 민감정보(건강정보) 별도 동의, 만 14세 이상 확인, 회원 탈퇴(개인정보 삭제 + 법정 보관 기록 익명화)
- 보안 헤더(HSTS, X-Frame-Options 등), 회원·액션별 요청 수 제한

## 테스트

```bash
npm test                                   # 규칙 단위 테스트 + 실제 PostgreSQL 통합 테스트 (TEST_DATABASE_URL)
BASE_URL=http://localhost:3000 node scripts/e2e-server.cjs   # 서버 모드 종단 간 (28개 시나리오)
```

통합 테스트는 동시 질문 6건 중 잔액이 허용하는 2건만 성공하는지, 같은 결제 승인이 5번 동시에 와도 1번만 지급되는지, 결제 금액 조작이 막히는지 확인합니다.
종단 간 테스트는 충전 → 결제취소 → 질문 → 치료사 가입·서류 → 관리자 승인 → 답변·채택·평가 → 신고 처리 → 환전 → 라운지 → 멤버십·크론 → 회원 탈퇴까지 확인합니다.

## 배포 (예: Vercel + Neon/Supabase PostgreSQL)

1. PostgreSQL을 만들고 `DATABASE_URL`을 준비합니다. 로컬에서 `DATABASE_URL=... npm run db:migrate`를 실행합니다.
2. Vercel에 저장소를 연결하고 `.env.example`의 값을 모두 환경변수로 등록합니다. `DEV_LOGIN`은 넣지 않습니다.
3. **카카오 디벨로퍼스**: 앱 생성 → 카카오 로그인 활성화 → Redirect URI `https://도메인/api/auth/callback/kakao` → `AUTH_KAKAO_ID/SECRET`
   (관리자 지정에 이메일을 쓰려면 이메일 동의항목 필요 · 비즈 앱 전환)
4. **네이버 개발자센터**: 애플리케이션 등록 → Callback `https://도메인/api/auth/callback/naver` → `AUTH_NAVER_ID/SECRET`
5. **토스페이먼츠**: 개발자센터 테스트 키로 결제·취소·정기결제를 확인 → 가맹점 계약·심사 후 라이브 키로 교체. 정기결제(빌링)는 별도 계약이 필요합니다.
6. **크론**: `vercel.json`이 10분마다 `/api/cron/sweep`을 호출합니다 (`CRON_SECRET`). 다른 호스팅에서는 외부 크론으로 `Authorization: Bearer <CRON_SECRET>` 헤더를 붙여 호출하세요.
7. `ADMIN_EMAILS`에 운영자 이메일을 넣고 그 계정으로 로그인하면 `/admin`이 열립니다.
8. `src/lib/config.ts`의 `BUSINESS`(상호·대표·사업자번호·통신판매업 신고번호·주소·연락처)를 실제 정보로 바꿉니다.

`ENCRYPTION_KEY`는 반드시 안전한 곳에 백업하세요. 잃어버리면 면허번호·계좌·빌링키를 복호화할 수 없습니다.

## 출시 전 체크리스트 (코드 밖에서 해야 할 일)

- [ ] 사업자등록, **통신판매업 신고**, 푸터의 사업자 정보 교체
- [ ] **토스페이먼츠 가맹점 계약** (의료·건강 상담 관련 업종이라 심사가 까다로울 수 있으니 서비스 성격을 정확히 설명) + 정기결제 계약
- [ ] **법률 검토**
  - 전자금융거래법: 토큰을 사서 현금으로 바꾸는 구조가 선불전자지급수단 발행·관리업 등록 대상인지
  - 의료법: 물리치료사의 온라인 답변이 진료·진단 행위나 의료광고로 해석되지 않도록 서비스 범위와 문구 확인
  - 이용약관·개인정보 처리방침·환불 정책(`/terms`, `/privacy`, `/refund`): 현재 **초안**이며, 수탁 업체명 등 실제 정보 반영 필요
- [ ] 세무: 환전 시 원천징수(3.3%) 신고·지급명세서 제출 절차, 수수료 매출의 부가세 처리
- [ ] 치료사 면허 진위 확인 방법 확정 (예: 한국보건의료인국가시험원 면허 조회), 심사 기준 문서화
- [ ] 운영: DB 자동 백업, 오류 모니터링(Sentry 등), 고객센터 이메일·전화 개설

## 알려진 한계와 다음 단계

- **채팅**은 3초 간격 폴링입니다. 사용자가 늘면 웹소켓이나 실시간 DB(Supabase Realtime 등)로 바꾸세요.
- **요청 수 제한**은 서버 메모리 기준이라 서버 여러 대로 운영하면 Redis(Upstash 등)로 바꿔야 합니다.
- 첫 화면 데이터(`/api/bootstrap`)는 최근 질문 수백 건을 한 번에 내려줍니다. 규모가 커지면 페이지 단위 API로 나누세요.
- 답변 등록·채택 알림(카카오 알림톡·이메일·푸시)은 아직 없습니다.
- 환전 계좌의 예금주 실명 확인은 관리자가 직접 합니다. 자동화하려면 1원 인증이나 계좌 실명조회 API를 연동하세요.
