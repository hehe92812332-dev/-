# PT 브릿지 운영 준비 가이드

코드는 준비되어 있습니다. 이 문서는 **운영자가 직접 해야 하는 일**을 순서대로 정리한 것입니다.
위에서부터 차례로 체크하면 됩니다. 서로 기다려야 하는 일(➜)이 있으니 순서를 지켜 주세요.

> 법·세무 내용은 2026년 10월에 확인한 일반 정보입니다. 최종 판단은 변호사·세무사에게 받으세요.

---

## 전체 흐름 한눈에

```
[1주차] 이름·도메인·비밀키 ─┐
        사업자등록 ──────────┼─➜ 사업용 계좌 ─➜ 토스페이먼츠 가맹 신청 ─➜ 구매안전서비스 확인증 ─➜ 통신판매업 신고
        변호사·세무사 상담 ──┘                      (심사 1~3주)
[2주차] Vercel·DB·저장소 가입 ─➜ 테스트 배포(테스트 결제 키) ─➜ 카카오·네이버 로그인 등록·검수
[3~4주] 치료사 초기 회원 모집 · 건강 소식 검수 · 리허설 ─➜ 라이브 결제 키로 교체 ─➜ 출시
```

가장 오래 걸리는 일은 **토스페이먼츠 심사**와 **법률 검토**입니다. 첫날 바로 시작하세요.

---

## 1단계 · 오늘 바로 (무료, 1~2시간)

- [ ] **서비스 이름 상표 검색**: [KIPRIS](https://www.kipris.or.kr)에서 "PT 브릿지", "피티브릿지"를 검색합니다. 같은 분류(제44류 의료·제35류 광고/중개·제42류 소프트웨어)에 이미 등록된 상표가 있으면 이름을 바꾸는 게 싸게 먹힙니다.
- [ ] **도메인 구매**: 가비아·후이즈 등에서 구매합니다 (예: `ptbridge.kr`).
- [ ] **운영용 이메일 만들기**: `help@도메인` 같은 고객센터 주소를 만듭니다 (Google Workspace, 네이버 웍스 등). 개인 이메일을 그대로 쓰지 마세요.
- [ ] **비밀번호 관리자 준비**: 1Password·Bitwarden 등. 아래 키와 각종 계정 정보를 여기에만 보관합니다.
- [ ] **비밀키 2개 만들기**: 터미널에서 아래를 두 번 실행해 각각 저장합니다.
  ```bash
  openssl rand -base64 32   # → AUTH_SECRET
  openssl rand -base64 32   # → ENCRYPTION_KEY  ※ 잃어버리면 면허번호·계좌 정보를 영영 못 읽습니다. 반드시 두 곳 이상에 백업
  ```

## 2단계 · 사업자 만들기 (1주차)

- [ ] **개인사업자 vs 법인 결정**: 회원 돈(충전금)을 맡아 두는 사업이라 책임 범위를 생각하면 법인이 유리할 수 있습니다. 세무사와 상담 때 함께 정하세요.
- [ ] **사업자등록**: 홈택스(개인) 또는 등기 후 세무서(법인). 업종은 세무사와 상의하되, 온라인 중개 플랫폼에 맞는 업종(예: 정보서비스업·전자상거래 중개)으로 등록합니다.
- [ ] **사업용 계좌 개설**: 결제 대금 정산과 치료사 환전 이체에 씁니다.

## 3단계 · 전문가 상담 (1주차에 예약, 병행)

이 플랫폼은 **충전금 · 현금 환전 · 건강 상담**이 섞여 있어서, 출시 전에 아래 질문을 그대로 들고 가면 됩니다.

### 변호사에게 물어볼 것
- [ ] **전자금융거래법(선불전자지급수단)**: 회원이 현금으로 토큰을 사서 다른 회원(치료사)에게 지급하고, 치료사가 현금으로 환전하는 구조입니다. 선불업 등록 대상인가요?
  - 참고: 2024년 9월 개정법 기준, 발행잔액 30억 원·연간 총발행액 500억 원 미만이면 등록이 면제됩니다. 하나의 가맹점에서만 쓰이는 경우의 면제는 좁아졌습니다 ([금융위원회 보도자료](https://www.fsc.go.kr/no010101/82339)).
  - 우리 시뮬레이션(100만 명·1년)에서는 미사용 충전 잔액이 약 100억 원으로 추산됐습니다. 성장하면 기준을 넘을 수 있으니 **어느 시점에 무엇을 해야 하는지**까지 물어보세요.
- [ ] **의료법**: 물리치료사의 온라인 답변이 진료·진단으로 해석되지 않으려면 서비스 범위와 문구를 어떻게 정해야 하나요? 치료사 프로필·건강 소식이 의료광고에 해당하나요?
- [ ] **약관·개인정보 처리방침·환불 정책 검토**: 사이트의 `/terms`, `/privacy`, `/refund`가 초안입니다. 건강정보(민감정보)를 별도 동의로 받고 있다는 점도 함께 보여 주세요.

### 세무사에게 물어볼 것
- [ ] **치료사 환전금 원천징수 구분**: 지금 코드는 **사업소득 3.3%**로 계산합니다(`src/lib/config.ts`의 `WITHHOLDING_TAX_RATE`). 가끔 답변하는 치료사는 **기타소득(8.8%)**일 수도 있습니다. 반복적이면 사업소득, 일시적이면 기타소득으로 나뉩니다. 바꿔야 하면 숫자 하나만 고치면 됩니다.
- [ ] **토큰 판매의 부가세 시점**: 충전할 때와 질문에 쓸 때 중 언제 매출로 잡나요? 플랫폼 수수료(15%)는 어떻게 처리하나요?
- [ ] **원천징수 신고·지급명세서 제출 일정**: 보통 다음 달 10일까지 신고·납부합니다. 우리 상황에 맞는 일정을 확인하세요.

## 4단계 · 결제 (토스페이먼츠) ➜ 통신판매업 신고

순서가 중요합니다. **사업자등록 → 토스페이먼츠 계약 → 구매안전서비스 확인증 → 통신판매업 신고**

- [ ] **토스페이먼츠 개발자센터 가입** → **테스트 키**를 받습니다 (`NEXT_PUBLIC_TOSS_CLIENT_KEY`, `TOSS_SECRET_KEY`). 계약 전에도 테스트 결제로 전체 흐름을 시험할 수 있습니다.
- [ ] **가맹 신청**: 사업자등록증, 대표자 신분증, 정산 계좌, **사이트 주소**가 필요합니다.
  - 심사에서는 사이트에 약관·환불정책·사업자 정보가 표시되어 있는지 봅니다. 그래서 5단계 테스트 배포를 먼저 해 두는 것이 좋습니다.
  - "토큰 충전(선불)" 상품이라 심사에서 질문을 받을 수 있습니다. *"건강 상담 질문에 쓰는 이용권이고, 7일 내 미사용분은 결제 취소, 잔액은 수수료 10% 공제 후 환불"*처럼 정확히 설명하세요.
- [ ] **정기결제(빌링) 별도 신청**: 멤버십 자동 갱신에 필요합니다. 일반 결제와 따로 심사합니다.
- [ ] **구매안전서비스 이용확인증 발급**: 계약 후 토스페이먼츠 상점관리자에서 받습니다.
- [ ] **통신판매업 신고**: [정부24](https://www.gov.kr)에서 "통신판매업 신고"를 검색해 신청합니다(사업자등록증과 위 확인증 필요). 신고 후 등록면허세 고지서가 나오면 납부합니다.
- [ ] 계약이 끝나면 **라이브 키**로 교체합니다 (8단계).

| 무엇 | 추천 | 받아 올 값 | 주의 |
| --- | --- | --- | --- |
| 웹 호스팅 | **Vercel Pro** (유료) | — | 무료(Hobby) 플랜은 예약 작업을 **하루 1번**만 허용해서 이 프로젝트(10분마다 실행)는 배포가 실패합니다 ([Vercel 문서](https://vercel.com/docs/cron-jobs/usage-and-pricing)). 서버 지역은 서울(`icn1`)로 설정해 두었습니다 |

| 서류 파일 저장소 | Cloudflare R2 또는 AWS S3(서울) | `S3_BUCKET`, `S3_ENDPOINT`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` | 버킷은 **비공개**로 만드세요 (면허증 사본 보관) |
| 오류 알림 (선택) | Sentry | — | 연결이 필요하면 말씀해 주세요 |

## 6단계 · 소셜 로그인 (2주차, 검수 기간 있음)

도메인이 연결된 뒤 진행합니다. 아래 `도메인`은 실제 주소로 바꾸세요.

- [ ] **카카오 디벨로퍼스** ([developers.kakao.com](https://developers.kakao.com))
  1. 애플리케이션 추가 → 카카오 로그인 활성화
  2. Redirect URI: `https://도메인/api/auth/callback/kakao`
  3. **비즈 앱 전환**(사업자 정보 등록): 이메일을 받으려면 필요합니다. 관리자 지정(`ADMIN_EMAILS`)도 이메일로 합니다.
  4. 동의항목: 닉네임, 이메일
  5. REST API 키 → `AUTH_KAKAO_ID`, 보안 › Client Secret → `AUTH_KAKAO_SECRET`
- [ ] **네이버 개발자센터** ([developers.naver.com](https://developers.naver.com))
  1. 애플리케이션 등록 → 네이버 로그인, 이름·이메일 제공 선택
  2. Callback URL: `https://도메인/api/auth/callback/naver`
  3. Client ID → `AUTH_NAVER_ID`, Secret → `AUTH_NAVER_SECRET`
  4. 출시 전에 **검수 요청**을 합니다. 검수 전에는 등록한 테스트 계정만 로그인됩니다.

## 7단계 · 배포하기

- [ ] Vercel에 GitHub 저장소를 연결합니다.
- [ ] 환경변수를 등록합니다 (Vercel › Settings › Environment Variables). **`DEV_LOGIN`은 넣지 마세요.**

  | 변수 | 값 |
  | --- | --- |
  | `NEXT_PUBLIC_APP_MODE` | `server` |
  | `DATABASE_URL` | 5단계 DB 풀러 주소 |
  | `AUTH_SECRET` | 1단계에서 만든 값 |
  | `AUTH_URL` | `https://도메인` |
  | `AUTH_KAKAO_ID` / `AUTH_KAKAO_SECRET` | 6단계 |
  | `AUTH_NAVER_ID` / `AUTH_NAVER_SECRET` | 6단계 |
  | `ADMIN_EMAILS` | 운영자 카카오·네이버 계정 이메일 (쉼표로 여러 개) |
  | `ENCRYPTION_KEY` | 1단계에서 만든 값 (**절대 바꾸지 않기**) |
  | `PAYMENTS_PROVIDER` | `toss` |
  | `NEXT_PUBLIC_TOSS_CLIENT_KEY` / `TOSS_SECRET_KEY` | 처음엔 테스트 키 → 계약 후 라이브 키 |
  | `CRON_SECRET` | `openssl rand -base64 32`로 하나 더 만들기 |
  | `STORAGE_DRIVER` | `s3` |
  | `S3_BUCKET` / `S3_REGION` / `S3_ENDPOINT` / `S3_ACCESS_KEY_ID` / `S3_SECRET_ACCESS_KEY` | 5단계 (R2는 `S3_REGION=auto`) |

- [ ] 내 컴퓨터에서 운영 DB를 준비합니다 (Node.js 설치 필요):
  ```bash
  git clone <저장소 주소> && cd <폴더> && npm install
  DATABASE_URL="운영 DB 주소" npx drizzle-kit migrate        # 표 만들기
  DATABASE_URL="운영 DB 주소" npx tsx --conditions=react-server scripts/news-import.ts   # 건강 소식 30편을 '검수 대기'로
  ```
  ⚠️ 운영 DB에는 `db:seed`(데모 데이터)를 **절대** 실행하지 마세요.
- [ ] `ADMIN_EMAILS`에 넣은 계정으로 로그인해 `/admin`이 열리는지 확인합니다.
- [ ] **사업자 정보 교체**: `src/lib/config.ts`의 `BUSINESS`(상호, 대표자, 사업자번호, 통신판매업 신고번호, 주소, 이메일, 전화, 개인정보 보호책임자)를 바꿉니다. 이 정보는 화면 아래쪽(푸터)과 약관에 표시됩니다.
- [ ] **개인정보 처리방침의 위탁 업체 반영**: 실제로 쓰는 Vercel, DB 업체, 저장소 업체, 토스페이먼츠, 카카오, 네이버를 `/privacy`의 "처리 위탁" 표에 적습니다.

> 사업자 정보와 위탁 업체 목록을 알려 주시면 이 두 가지는 바로 반영해 드릴게요.

## 8단계 · 출시 전 준비 (3~4주차)

- [ ] **치료사 초기 회원 모집 (가장 중요)**: 답변할 치료사가 없으면 질문이 기한 내에 답을 못 받고 환불됩니다. 출시 전에 **최소 20~30명**, 가능하면 등급별로 고르게 승인해 두세요. 지인 네트워크, 학회·스터디 모임, 물리치료학과 동문회 등을 활용하세요.
- [ ] **면허 확인 방법 정하기**: 지금은 관리자가 업로드된 면허증·경력증명서를 직접 보고 승인합니다. 면허 진위를 어떻게 확인할지(발급 기관 조회 가능 여부 등) 정하고 심사 기준을 문서로 남기세요.
- [ ] **건강 소식 30편 의학 검수**: 관리자 콘솔 › 건강 소식에서 한 편씩 읽고 승인합니다. 승인하면 빈 날짜에 하루 한 편씩 자동 예약됩니다. 기본 글은 일반 자료를 바탕으로 한 초안이므로, **면허를 가진 전문가**가 확인해야 합니다.
- [ ] **리허설 (테스트 키로)**: 운영 사이트에서 직접 해 봅니다.
  - [ ] 환자 계정: 충전 → 결제 취소 → 다시 충전 → 질문
  - [ ] 치료사 계정: 가입·서류 업로드 → 관리자 승인 → 답변
  - [ ] 채택·평가 → 치료사 환전 신청 → 관리자 화면에서 계좌 확인 → 실제 이체 → "이체 완료"
  - [ ] 멤버십 가입 → 자동 갱신 확인
  - [ ] 10분 뒤 Vercel › Cron Jobs에서 `/api/cron/sweep`이 성공(200)했는지 확인
- [ ] **라이브 결제 키로 교체** → 소액으로 실제 결제 1회 → 결제 취소로 환불까지 확인
- [ ] **고객센터 운영 시간 정하고** 사이트·약관에 표시

## 9단계 · 출시 후 운영 루틴

### 매일 (관리자 콘솔 `/admin`, 15~30분)
- [ ] **서류 심사**: 새 치료사 승인/보완 요청 (늦으면 가입 이탈)
- [ ] **신고 처리**: 잘못된 의료 정보, 개인정보 노출 등
- [ ] **환전·환불 이체**: 표시된 계좌로 은행 이체 후 "이체 완료" (예금주 이름이 회원 실명과 맞는지 확인)
- [ ] **건강 소식 일정**: 앞으로 14일 중 빈 날(빨간색)이 없게 원고를 승인·예약
