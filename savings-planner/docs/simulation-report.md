# 10만 명 시뮬레이션: 발견한 문제와 해결

숫자 표 전체는 [simulation-results.md](simulation-results.md)에 있고 `npm run simulate:compare`로 똑같이 다시 만들 수 있습니다.

## 어떻게 시험했나

**실제 사용자 데이터가 아닙니다.** 시드를 고정한 난수로 만든 가상 사용자 100,000명입니다(`simulation/population.js`).

| 구성 | 내용 |
| --- | --- |
| 사용자 유형 8개 | 대학생·아르바이트, 사회초년생, 직장인, 고소득 직장인, 맞벌이, 프리랜서, 자영업, 은퇴·연금 |
| 목표 7개 | 비상금, 여행, 자동차, 결혼 자금, 전세·주택, 목돈, 대출 상환 (금액·기간은 유형별로 다르게) |
| 지출 12개 항목 | 고정비 / 필수 생활비 / 선택 지출, 항목별 월 변동 폭 |
| 입력 습관 | 쉼표(12%), "300만원"(5%), 목표 날짜로 입력(10%), 이율 0.035(3%), 이율 오타 35(1%), 빈칸, 0개월·음수·빈 목표 같은 잘못된 값 |
| 지출 기록 | 55%는 카드 내역으로 최근 3개월 입력, 45%는 기억으로 적음(선택 지출은 최대 25% 적게 적는 경향) |

계획을 받은 사용자는 기간 끝까지 한 달씩 실제로 살아 봅니다(`simulation/simulate.js`).

- 월급날 목표 통장으로 자동이체
- 소득 변동(프리랜서·자영업은 ±25~60%), 실직(월 0.2~0.6%)
- 돌발 지출: 매달 5% 확률로 수입의 10~80%
- 줄이라는 지출은 사람마다 지키는 정도(35~100%)가 다르고, 많이 줄이라고 할수록 덜 지킵니다
- 이자는 실제 세후 이율(이자소득세 15.4%)로 붙습니다
- 생활비가 모자라면 적금을 깨서 메웁니다

결과를 보고 10가지 규칙으로 컴플레인을 판정했습니다(C1~C10).

## 첫 버전(v1)에서 나온 문제

컴플레인이 1건 이상인 사용자가 **99.3%**, 계획대로 해서 목표를 채운 사람은 **22.3%**였습니다.

| 문제 | 규모 | 원인 |
| --- | --- | --- |
| 금액 자동이체가 불편 (C8) | 68% | 월 저축액이 1,234,567원처럼 나옴 |
| "가능"이라더니 실패 (C3) | 49% | 이자를 세전으로 계산, 들쭉날쭉한 소득을 평균으로 계산, 기억으로 적은 지출을 그대로 믿음, 돌발 지출 여유 없음 |
| 생활비 부족으로 적금 깸 (C4) | 34% | 남는 돈을 거의 다 저축으로 잡음 |
| 계산 결과가 NaN (C1) | 27% | `3,000,000`, `300만원`, 목표 날짜 입력을 숫자로 못 읽음 |
| 과한 절약 요구 (C5) | 26% | 선택 지출 50%, 필수 생활비 20%까지 깎음 |
| 대안 없음 (C6) | 9% | "기간 연장" 하나만 제시 |
| 잘못된 입력을 그대로 계산 (C2) | 1.5% | 0개월·음수·빈 목표에 오류 안내가 없음 |

## 고친 내용 (v2, `planner.js`)

| 해결 | 대상 컴플레인 |
| --- | --- |
| 금액 해석기: `3,000,000` · `300만원` · `1억 5천만` · `3.5만` 모두 인식, 입력칸 아래에 "= 300만원"으로 바로 보여줌 | C1, C2 |
| 기간을 개월 수나 목표 날짜로 입력. 0개월, 600개월 초과, 빈 목표, 음수 지출은 계산하지 않고 이유를 안내 | C1, C2 |
| 이율 0.035 → 3.5%로 해석, 15% 초과는 오타로 보고 0%로 보수 계산(경고 표시), **이자소득세 15.4% 반영**(비과세 선택 가능) | C3 |
| 들쭉날쭉한 소득은 **평균 − 0.75×표준편차**(최저 소득 이상)로 계획, 기록이 없으면 80%로 계산 | C3, C4 |
| 최근 3개월 기록이 있으면 평균을 쓰고, 기억으로 적은 지출은 과소 추정분(선택 12%, 필수 5%)을 여유분으로 남김 | C3, C4 |
| 수입의 5%를 **생활비 통장 여유분**으로 남김 | C4 |
| 감축 한도: 고정비 0%, 필수 생활비 10%, 선택 지출 30%. 권장 비중을 넘는 항목부터 줄임 | C5 |
| 줄이기로 한 금액의 40%는 못 지킬 수 있다고 보고 여유분에 포함 | C3, C4 |
| **3개월마다 중간 점검**: 생활비 통장에서 여유분(수입의 절반, 변동 소득은 한 달 지출)을 넘는 돈은 목표 통장으로 옮기고, 실제 지출·잔액으로 다시 계산 | C3, C4 |
| 불가능할 때 대안 5~6개: 기간 연장, 목표 조정, 기간 1.25·1.5·2배 절충안, 필요한 추가 수입, 적자면 가장 큰 고정비부터 점검 | C6 |
| 월 저축액 1,000원 단위 올림, 예산 + 저축 + 여유분 = 수입이 항상 맞도록 정리 | C8, C9 |
| 이미 달성했거나 이자만으로 달성되면 "추가 저축 불필요" | C7 |

개선은 한 번에 하지 않고 시뮬레이션을 돌리며 단계별로 진행했습니다.

| 단계 | 컴플레인 사용자 | 목표 달성 |
| --- | --- | --- |
| v1 | 99.3% | 22.3% |
| 입력 해석·세후 이자·보수적 소득·감축 한도·대안·반올림 | 59.3% | 58.7% |
| + 3개월 점검과 여유분 옮기기 | 52.7% | 88.4% |
| + 감축 미이행분 여유, 변동 소득 더 보수적으로 | 50.1% | 92.7% |
| + 절충안(기간 1.25·1.5·2배) 추가 | **48.8%** | **92.5%** |

## 최종 결과

- 계산 오류, 입력 인식 실패, 과한 절약 요구, 금액 단위, 합계 불일치, 이미 달성 안내: **모두 0건**
- "가능"이라더니 실패: 49.0% → **4.6%**
- 적금을 2번 이상 깸: 33.7% → **12.0%**
- 계획을 따른 사람의 목표 달성률: 22.3% → **92.5%**

## 남은 문제 (솔직하게)

1. **"대안 없음"(C6)이 8.8% → 35.4%로 늘었습니다.** v1은 무리한 계획을 "가능"이라고 내줬다가 실패했고, v2는 안전 여유를 두기 때문에 불가능 판정이 늘었습니다. 세부 원인은 다음과 같습니다.
   - 18,253명: 줄일 수 있는 만큼 줄이고 안전 여유를 남기면 저축할 돈이 없음. 대학생, 프리랜서, 사회초년생에게 많습니다. 서비스는 "적자부터 해결"과 "가장 큰 고정비 점검"을 안내합니다. 남는 돈이 조금 있는 사람에게 "작게라도 시작하기" 계획을 줄지는 정책 결정이 필요합니다.
   - 7,260명: 기간을 2.2배로 늘려도 목표의 60%에 못 미침(예: 월 250만 원 소득으로 3년 안에 2억 원). 계산으로 풀 수 있는 문제가 아닙니다.
   - 9,927명: 대안은 있었지만 사용자의 참을성(기간 1.2~2.2배, 목표 60~90%) 밖이었습니다. 개선 여지가 가장 큰 부분입니다.
2. **적금을 깨는 사람(C4)이 아직 12%입니다.** 대부분 소득 변동이 큰 프리랜서와 자영업자, 돌발 지출이 기간 초반에 생겨 생활비 통장 여유분이 쌓이기 전인 경우입니다. 현재 저축액 일부를 생활비 통장 비상금으로 먼저 떼어 두는 옵션을 검토할 만합니다.
3. 시뮬레이션은 가정에 기반합니다(돌발 지출 확률, 절약을 지키는 정도, 사용자의 참을성 등). 실제 서비스를 열면 익명 통계로 이 값들을 실제 데이터에 맞게 보정해야 합니다.
4. v2는 사용자 한 명의 기간 전체를 시뮬레이션할 때 점검마다 다시 계산하므로 10만 명 기준 약 20초 걸립니다. 실제 화면에서 계획 한 번 계산하는 데는 1ms 미만입니다.
